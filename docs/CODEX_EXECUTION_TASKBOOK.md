# JLZ-EDU-SK-087 Codex执行任务书

## 1. 基线

- 任务编号：`JLZ-EDU-EXPANSION-30-FULL-DELIVERY`
- 候选来源：`CAND-016`
- 正式产品：`JLZ-EDU-SK-087` / 作业负担与有效性审查
- 类型：Skill
- 批次：2
- 业务中心：10 教学质量与学习证据中心
- 版本基线：`EDUCATION_BASELINE_V1.0.0`
- 产品版本：`1.0.0`
- 许可证：Apache-2.0

## 2. 用户、痛点与目标

- 用户：教研主管、年级组长、班主任、教学负责人
- 痛点：各学科独立布置作业，单科看似合理，累计后可能超时；重复抄写和低效任务也会侵蚀学习时间。
- 目标：按年级、学科和周期汇总作业，估算时间并审查任务与目标对齐、重复度、可完成性和反馈价值。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `assignments` | 跨学科作业清单 | array | 是 |
| `grade` | 年级 | string | 是 |
| `student_group` | 学生群体 | string | 是 |
| `learning_objectives` | 目标 | array | 是 |
| `parent_feedback` | 家长反馈摘要 | string | 否 |
| `schedule_context` | 周内时间安排 | string | 是 |

## 4. 工作流

1. 建立周作业表
2. 汇总时间
3. 检查目标对齐
4. 标记重复/低效
5. 评估反馈闭环
6. 给出减负增效方案

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点各科作业清单、预计用时、知识点目标、题型、提交方式、班级水平、家长反馈和周末安排，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕按年级、学科和周期汇总作业，估算时间并审查任务与目标对齐、重复度、可完成性和反馈价值。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按建立周作业表 → 汇总时间 → 检查目标对齐 → 标记重复/低效 → 评估反馈闭环 → 给出减负增效方案设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由业务负责人复核输入事实、关键假设和最终成果适用范围。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `周作业负荷表`
- `跨学科冲突`
- `替代任务建议`

## 7. 差异化与排重

- 与现有产品：分层作业产品按单科生成难度任务；本产品做跨科总量与有效性审查，属于上游质量门禁。
- 排重检查：部分重叠；共享作业对象，但本产品不主要出题，专门审查总负担和任务价值。
- 独立理由：可审核人工或外部生成的作业，不依赖现有生成器。

## 8. 安全与人工门禁

- 复核角色：业务负责人
- 复核范围：输入事实、关键假设和最终成果适用范围
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。

## 9. 测试
